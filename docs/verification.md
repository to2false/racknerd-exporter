# 验证与发布检查

## Rust 与接口行为

开发时已通过 `cargo fmt --check`、`cargo test --locked`（10 项单元测试、5 项集成测试）和 `cargo clippy --locked --all-targets -- -D warnings`。发布工作流重复这些检查。

测试覆盖：XML 片段与 `<ctrl>` 根节点、模拟响应、online/offline/disabled/未知状态、畸形数据、非有限数字、超额配额、并发请求合并、缓存过期后的失败与恢复、超时、HTTP 错误、禁止重定向、响应大小上限，以及凭据/上游正文不进入指标。

`tests/fixtures/ctrl-info.xml` 为模拟数据，不含真实实例身份、资源配置或用量。测试使用回环地址中的模拟服务器，不需要 RackNerd 凭据，也不会访问实际 VPS。

## 监控链路

已完成真实 API 的只读认证查询，并验证 Prometheus 抓取与 Grafana 展示。公开仓库不保留真实响应、服务器编号、个人域名、数据源 UID、用户名或现场用量记录。

汇总仪表盘默认近 24 小时、每 15 秒刷新。服务器 API 缓存保持 1 小时；sing-box 速度是近一分钟平均值，时段用量由计数器增量计算。已通过浏览器检查用户表格合并、排序、单位、上下行曲线和默认首页跳转。

匿名查看需要在部署者自己的 Grafana 中配置；已验证 Viewer 可以读取仪表盘和数据，但不能编辑、保存或删除。仓库不会自动变更部署者的匿名权限或网络访问控制。

## 发布前脱敏

- `.env` 与其他私密配置不进入 Git 或镜像上下文。
- 提交使用 GitHub noreply 邮箱。
- 用真实本地凭据进行内存中的精确匹配检查，仅报告文件名，不打印凭据。
- 对待提交快照和 Git 历史运行 Gitleaks，并开启输出脱敏。
- 检查文档、仪表盘和测试样本中的个人域名、服务器编号、本机路径和实例身份。

## 镜像发布

GitHub Actions 在两个原生 runner 上分别构建 `linux/amd64` 和 `linux/arm64`，通过后发布 GHCR 多架构 manifest。拉取请求运行测试和镜像构建，只有主分支和版本标签发布镜像。

镜像以非 root 用户运行，包含 CA 证书；运行时配置通过环境变量或挂载的密钥文件提供。发布工作流不需要实际 RackNerd API 凭据。
